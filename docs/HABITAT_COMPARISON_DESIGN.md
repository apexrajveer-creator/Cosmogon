# Controlled habitat experiments and trajectory comparison

Prepared 2026-10-08 after recording checkpoint `db481ff`. Directive phases 9/16 require usable experiments and comparisons. Existing habitat controls, ordinary configuration edits, deterministic advancement, protected exports and bounded readers provide the mechanism; extending them avoids a second simulation. No new physical law or equipment calibration is introduced. NASA BVAD nominal crew exchange and NIST reaction sources retain their existing assumptions and validity limits.

Build one shared typed sweep plan: select an existing habitat, one explicitly supported configuration parameter and 2–16 distinct finite values, 1–1024 samples, positive interval and at most 30 days. Bound aggregate observations to 8192. Every branch starts from the same exact saved world and applies one ordinary configuration edit at the same time. Old-configuration remainders finish through that existing edit path. Initial inventory remains fixed; changing battery capacity does not fill the battery. Reaction parameters require already enabled equipment. Validate all branch edits before creating an exclusive output folder. Stream actual per-run habitat bundles, retain common base and plan, and write completion manifest last. The native session refuses read-only reference worlds; headless inputs are explicit sandbox saves. Refuse existing exports. Failures may leave a clearly incomplete newly created folder, never overwrite old results.

Expose the same mechanism in CLI and native Recordings. Native execution uses a captured independent world clone on a worker, preserves the live world and previous recorded views on failure, and opens the first/last completed runs on success. Show chosen units/assumptions and output location; ordinary users can run it without terminal tools. Parameter ranges are bounded by the existing model, not advertised as hardware capabilities. A sweep measures modeled sensitivity, not predictive uncertainty or optimization proof.

Compare any two independently validated recordings using the same metric and either exact world time or exact relative elapsed time. Only stored timestamps match; no interpolation, extrapolation or nearest-time subtraction. Interval quantities also require identical positive completed interval duration and habitat interval end, aligned in the selected coordinate. Mismatched interval support is explicit. Graph both actual series with distinct points/colours and shared units/axes, preserve gaps, and display exact A, B, B−A where compatible. Source/config/site/initial state differences remain inspectable; arbitrary pairs do not imply a controlled experiment or causality.

Shared comparison JSON/CSV retains both summaries, selected alignment, actual timestamps, row indices, availability and differences. Native photo metadata records both original rows and comparison support, separately from live state. Failed comparison imports preserve the previous partner. Automated flags use the same checks before GPU startup. No save schema, default universe or golden change.

Acceptance: byte-exact deterministic sweep replay; independently calculated single-knob differences and unchanged other inputs/inventory; optional equipment/finite capacity/reference/output refusals before writing; actual snapshot/unmatched/gap/shifted-time comparisons; supported interval subtraction only; transactional native imports and sweep isolation; actual graph captures with shared inspected values; full tests, clippy, packaging and ordinary run. Physical greenhouse exchange, confidence intervals, calibration, large multi-parameter optimization and the complete directive remain separate unfinished work.

Primary methodological check: [NIST/SEMATECH, one variable at a time](https://www.itl.nist.gov/div898/handbook/pri/section2/pri212.htm), checked 2026-10-08. A single-factor series cannot identify interactions between multiple changed inputs. Product implication: label this as conditional modeled sensitivity and retain other settings; do not advertise global optimization or full uncertainty analysis. Exact-time matching is a deliberate product rule to avoid silently inventing observations, not an asserted NIST algorithm.
