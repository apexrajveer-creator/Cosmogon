Use f64 system-local inertial simulation axes, metres and metres/second. Initial authored position/velocity relative to a selected existing body must include that body's actual translational position AND velocity at the creation time. Do not add galactic origin to physical state or treat body-fixed coordinates as inertial velocities. Position plus three velocity components and a named frame/time form an explicit initial state. [JPL NAIF frame documentation](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/req/frames.html) distinguishes position rotation from state transformations; [Horizons manual](https://ssd.jpl.nasa.gov/horizons/manual.html) documents state vectors, centers, axes and epochs. These references guide frame honesty; this is the application's own existing simulation frame and clock, not a new JPL/SPICE precision claim.

Sample the existing system's star, companion and present bodies in deterministic vector order and apply Newtonian test-particle gravity, with the same `G` and mass conventions already used by the shared physics. [NASA Glenn's gravity explanation](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/rocket-weight/) supports inverse-square gravity and the contribution of multiple sources. Validate negligible vehicle backreaction against the initial parent mass; report the test-particle approximation, point-mass force fields and existing source ephemeris interpolation. Do not soften near-contact gravity without a physical model or change original body trajectories behind the user's back.

Use a fixed world scheduler grid, with bounded smaller steps split at commands and fuel depletion. A gravity-kick / exact finite-mass powered-drift / gravity-kick operator preserves the existing shared ideal velocity change while integrating displacement from the changing mass. The powered displacement formula needs a deterministic stable small-mass-fraction branch; do not use final velocity times the entire burn. Retain the same actual removed propellant, impulse and explicit residuals. Coast retains finite mass and moves under gravity. Verify vacuum displacement analytically, gravity convergence and angular-momentum behavior, finite cutoff, opposite directions, invalid-state atomicity and exact world replay under different caller chunking/save reloads.

Physical contact is an explicit modeled spherical boundary, not a safe landing. Detect crossing even when both endpoints lie outside a body; retain first-contact time/position/velocity and only the fuel consumed before it. Terrain collision/landing safety, drag/heating/entry, attitude, staging, powered hardware limits, docking, source uncertainty and physical delivery remain separately incomplete. Unsupported states must stop with an explicit retained reason rather than advance with fabricated zero gravity. Creating a craft starts journaled sandbox state; it does not extract unlimited cargo from a settlement. All masses are explicit authored initial-condition assumptions until a later loading/transfer mechanism conserves the same world stores.

The existing scheduler assigns habitats slot 4 and currently removes that slot when the last habitat is removed. Adding a vehicle task must preserve task indices: retain a finite NEVER placeholder when later tasks exist and activate it when a habitat is added. Absent worlds/golden must remain byte-identical. Active vehicle worlds deliberately change state/fingerprints with new model pins. Budgeted time advancement must remain responsive and show real lag instead of skipping unresolved flight. High-speed long flight, exact terrain support, manual interaction and independent empirical validation require later evidence; do not claim the phase complete from core tests.
