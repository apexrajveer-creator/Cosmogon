# Native cinematic paths: evidence and mechanism

Prepared before implementation, 2026-10-08. This is the next connected build after completed-interval habitat WHY, addressing master directive section 23. Use the existing f64 camera, presentation controls, viewpoint identities and native capture pipeline; do not create a web renderer or mutate Universe behind edits.

Evidence: [glam 0.30.10 DQuat](https://docs.rs/glam/0.30.10/glam/f64/struct.DQuat.html), pinned by Bevy in Cargo.lock, supplies normalized quaternion interpolation; [Blender keyframe documentation](https://docs.blender.org/manual/en/latest/animation/keyframes/introduction.html) describes interpolation between explicit timed keys. [Blender animation guidance](https://developer.blender.org/docs/features/interface/human_interface_guidelines/animations/) distinguishes constant-speed interpolation and transition timing. These support presentation mechanisms, not spacecraft dynamics or physical trajectory claims.

Engineering inference: a bounded app-only path with explicit timed keyframes, common world/reference-object identity, f64 relative position interpolation, normalized orientation SLERP, lens/colour interpolation and linear or smoothstep segment timing is a coherent first slice. Support opt-in current-object look-at with explicit stable target identity and geometric degeneracy handling. Enforce finite values, strictly increasing times, bounded file/key counts, protected versioned import/export and transactional edits. Never interpolate raw quaternion components without normalization or hide a missing anchor by falling back to another object.

Playback/scrub must use one shared pose evaluator, hold endpoints and identify presentation seconds separately from simulation time. Replay should stop on world/generation changes, a missing/destroyed anchor, return to menu or manual camera navigation; pausing/stopping leaves a reviewable pose and user-controlled lens preferences. No invisible time rewind or automatic simulation-rate mutation. Simulation acceleration synchronization, changing anchors mid-shot, spline/arc-length control, recorded video and depth-of-field remain later acceptance gates unless implemented and separately verified.

Provide native authoring from the current view and saved viewpoints, duration/easing/look-at controls, selected key editing/removal, play/pause/stop/scrub, persistent protected definitions and metadata. Provide explicit headless definition/pose capture for reproducible QA rather than a fake canned path. Bounded imports validate the entire path before changing camera/lens; unknown/future files remain protected. No new dependencies or save/golden changes.

Verify endpoints, intermediate pose, antipodal quaternions, extreme astronomical coordinates, invalid timings/inputs, deleted anchors, world/generation resets and no Universe mutations. Inspect actual native authoring and start/mid/end captures; sustain ordinary packaged playback. Controls must expose transitions and recovery and avoid starting camera motion automatically for a user who only opens the panel.
