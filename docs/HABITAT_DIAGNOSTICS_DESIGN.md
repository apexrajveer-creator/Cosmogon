# Habitat WHY diagnostics: evidence and mechanism

Prepared before implementation, 2026-10-08. This is the next connected build after equipment sonification, addressing the master directive's WHY control and research transparency. It remains a local completed-interval explanation, not a universal historical cause graph.

Evidence: the deterministic habitat engine retains its interval configuration, irradiance, generated/requested/delivered/unserved power, battery losses/curtailment, processed/recovered water, nominal crew-cycle fraction, explicit reactor constraints and signed thermal terms. These are authoritative model outputs. [NASA BVAD Rev2](https://ntrs.nasa.gov/api/citations/20210024855/downloads/BVAD_2.15.22-final.pdf), Table 3-31, supports the already implemented nominal crew interface rates; the electrolysis/Sabatier source memos support their existing reference reactions. None of these sources validates assumed equipment performance or predicts an individual crew member's health.

Engineering inference: expose those actual dependencies as a shared, read-only report rather than recomputing hypothetical physics from current inventories. A researcher can then trace a muted equipment voice or a power/resource outcome to the same numbers used by the simulation, export the explanation, and distinguish an actual constraint from an unknown cause.

Implement a shared engine diagnostic report and native WHY view. Use completed interval configuration exclusively. Recover exact served base/scrubber/recycler allocations from the explicit priority order; report the thermal control allocation as an aggregate because separate requested heater/pump watts were not retained. Optional reactor requested/served watts and constraints are already recorded. Never reconstruct pre-interval material constraints from post-interval stocks.

Power: identify firm supply, derived PV, battery bus contribution, charging input, curtailment and load demand from recorded balances. Thermal: show bus heat, battery losses, metabolic heat, electrolysis enthalpy debit, Sabatier reference heat, radiator rejection, conduction and stored heat, avoiding double-counting the heater already included in bus electricity. Air/crew: expose actual regulator/capture transfers and oxygen/CO₂/food/waste/reactor-store changes from retained nominal cycle and reaction budgets, without inferring a missing start constraint or health outcome. Reopen the same explanation for exact selected historical observations without changing the live world.

Water: distinguish nominal crew consumption, electrolysis draw, wastewater versus held raw-product processing, actual recovery and unrecovered brine; do not credit untreated new product in the same interval. Carry exact units, times, numerical residuals, source/model scope and unquantified uncertainty.

Explanation statements must name their evidence. Zero sampled illumination can be explained by star/geometric inputs but cannot establish dust, weather or a specific night without those inputs. Missing interval/configuration means unavailable decomposition, rather than zero demand. A recorded resource constraint is not an equipment fault. Design-alert thresholds are assumptions, not medical/safety limits. Avoid hypothetical forecasts and historical causal attribution from a single interval.

Reuse shared allocation diagnostics in equipment audio to remove duplicate inference. Expose diagnostics through the ordinary habitat report and CLI inspection/export without breaking existing study formats; legacy reports lacking this additive key remain readable, while present keys must match the shared result. Add protected direct diagnostic export and native photo context. Verify balances against actual powered/starved/reaction/legacy intervals, exact timestamps/configuration retention, unsupported gaps, report consistency and unchanged simulation/golden; inspect the native WHY view and sustain the packaged app before checkpointing.
