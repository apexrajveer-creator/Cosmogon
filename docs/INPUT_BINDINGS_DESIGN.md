# Input customization: evidence and next mechanism

Prepared before implementation, 2026-10-08, following authored camera paths. Master section 94 requires keyboard rebinding. Existing camera controls provide sensitivity/inversion/inertia, but camera and unmodified HUD keys are hardcoded. Connecting customization to both native input consumers and visible help addresses a real control gap; do not create a settings-only demonstration.

[Bevy 0.18.1 KeyCode](https://docs.rs/bevy/0.18.1/bevy/input/keyboard/enum.KeyCode.html) represents physical key locations, including letter/digit/navigation keys. Thus labels must explain physical locations rather than promise layout-aware text characters. Native `ButtonInput` provides held and just-pressed state; camera movement and HUD actions require different edge semantics. Inspect the pinned local API before implementing capture/release handling.

Engineering inference: use one app-only bounded typed action-to-key map for camera motion/look/orbit navigation and existing unmodified HUD actions. Preserve defaults and modifier chords. Reject duplicate assignments transactionally with a useful conflict label; keep Escape as a recovery/cancel key. Provide explicit capture/cancel, immediate runtime feedback, release gating to prevent the assigned key from also firing an action, reset and explicit persistence/export. Text-field focus and command modifiers continue to prevent accidental flight/actions. Cinematic manual interruption must use the rebound movement keys.

Use protected versioned complete definitions with bounded regular-file reads and strict key/action validation. Invalid/future persisted files remain untouched with a read-only warning and usable runtime defaults; export to a new file remains possible. No automatic rewriting or UserSettings/Universe schema migration. Expose a native Controls view, updated labels/help and explicit developer import/capture for reproducible verification. Unknown chords, mouse/controller bindings, international logical-key entry, assistive-technology acceptance and global OS shortcuts remain separate gates unless implemented.

Verify defaults, meaningful held/edge mappings, duplicate/reserved/unknown rejection, capture/release and cancellation, protected persistence/import, real native controls/help captures, ordinary camera playback and unchanged simulation/golden. Do not count manual keyboard/controller interaction as verified by metadata alone.
